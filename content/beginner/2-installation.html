dbt is a Python program, so setup is short: install the adapter, tell dbt which database to use, and run one command to prove the connection works. We use DuckDB — a full analytics database that runs in-process, with no server, no account and no cloud bill to manage.

{{icon:lightbulb}}
Why DuckDB for this course?

DuckDB is an embedded OLAP database: the whole warehouse lives in a single .duckdb file and runs inside your Python process. That means nothing to provision on a server and nothing to pay for — but the SQL and the dbt workflow are the same ones you would use against Snowflake, BigQuery or Redshift.

Install the toolchain

Always install dbt inside a virtual environment so it cannot clash with other Python projects. The dbt-duckdb package pulls in dbt-core and the DuckDB engine in a single step.

{{diagram:install|One adapter install gives you dbt-core, the DuckDB driver, a profile and a database file.}}
terminal bash 
# 1. Create an isolated environment
python3 -m venv .venv
source .venv/bin/activate

# 2. Install dbt-core + the DuckDB adapter together
pip install --upgrade "dbt-duckdb>=1.8"

# 3. Confirm it worked
dbt --version
PowerShell powershell 
# 1. Open PowerShell (not CMD), then create the environment
py -m venv .venv

# 2. Activate it — note the different path
.venv\Scripts\Activate.ps1

# 3. Install dbt-core + the DuckDB adapter
pip install --upgrade "dbt-duckdb>=1.8"

# 4. Confirm it worked
py -m dbt --version
{{icon:terminal}} Try itterminal
terminal bash 
dbt --version

Expected: a Core section showing a version like 1.9.0, then a Plugins section listing dbt-duckdb. If you see “command not found”, the virtual environment is not active — re-run the activate step.

Create the project the right way

This is the step the original guide got wrong. dbt init <name> creates a folder called <name> for you — so you must not create that folder first.

1
Move to the parent directory

Go where you keep projects. Do not mkdir the project folder.

2
Run dbt init

dbt asks which adapter to use; choose duckdb. It scaffolds the folder and writes a starter profile.

3
Enter the project

The new folder is ready to run.

terminal bash 
# ✅ Correct: dbt creates the folder named ecommerce_analytics
cd ~/projects
dbt init ecommerce_analytics
cd ecommerce_analytics
{{icon:triangle-alert}}
The nesting bug

The old page ran mkdir ecommerce-analytics && cd ecommerce-analytics and then dbt init ecommerce-analytics. Because dbt init also creates that folder, the project ended up nested one level too deep at ecommerce-analytics/ecommerce-analytics/. Run dbt init from the parent directory and never pre-create the folder.

Connect dbt to DuckDB with profiles.yml

dbt reads connection details from profiles.yml, kept outside the project so credentials never land in Git. By default dbt looks in ~/.dbt/; pass --profiles-dir . to use a copy that sits next to dbt_project.yml. The profile name must match the profile: key in dbt_project.yml.

~/.dbt/profiles.yml yaml 
# The profile name must match `profile:` in dbt_project.yml
ecommerce_analytics:
  target: dev
  outputs:
    dev:
      type: duckdb
      path: "ecommerce.duckdb"   # file is created on first run
      threads: 4
KeyWhat it does
typeSelects the adapter — duckdb for this course
pathLocation of the DuckDB database file dbt should open
threadsHow many models dbt may run in parallel
targetWhich output (here dev) is active for this run
{{icon:triangle-alert}}
profiles-dir is not a project key

Putting profiles-dir: "." inside dbt_project.yml does nothing — it is a command-line flag (or the DBT_PROFILES_DIR environment variable). Use dbt debug --profiles-dir . when your profile lives in the project folder.

Here is the matching project file, with correct keys (+materialized, not +materialization):

dbt_project.yml yaml 
name: 'ecommerce_analytics'
version: '1.0.0'
config-version: 2
profile: 'ecommerce_analytics'   # must exist in profiles.yml

model-paths: ["models"]
seed-paths: ["seeds"]
macro-paths: ["macros"]
target-path: "target"

models:
  ecommerce_analytics:
    +materialized: view           # default for new models

Verify the connection

dbt debug checks your Python, the adapter, and the warehouse connection, then reports on each one.

{{icon:terminal}} Try itterminal
terminal bash 
# Uses ~/.dbt/profiles.yml
dbt debug

# If profiles.yml sits next to dbt_project.yml:
dbt debug --profiles-dir .

Expected: every check reports OK and the run ends with All checks passed!. A failing connection check almost always means the profile name and profile: do not match.

Troubleshooting common setup problems

dbt: command not found

The virtual environment is not active, or dbt was installed globally under a different Python. Run the activate command for your shell and re-check with dbt --version.

Could not find profile named 'ecommerce_analytics'

The profile key in profiles.yml differs from profile: in dbt_project.yml, or dbt is looking in the wrong folder. Confirm the spelling and try dbt debug --profiles-dir ..

RuntimeError: Unable to import adapter duckdb

The dbt-duckdb package is missing from the active environment. Activate the venv and run pip install --upgrade "dbt-duckdb>=1.8".

My models disappear between runs

You are probably using an in-memory database. Set path to a real file such as ecommerce.duckdb so the tables persist.
